# Siril iPadOS 移植

使用真实 Siril 上游源码构建 iPadOS arm64 内核，再通过 C 接口连接 SwiftUI 界面。
固定上游提交：`6c0f8f3207b9cb712f7e04249217123a8ca66915`。

**目标是完整移植原版功能与操作流程；当前版本未完成该目标。**

[完整功能核对表](docs/FUNCTIONAL-PARITY.md)按原版主窗口 102 个动作和 73 个界面文件记录差异。
编译原版内核或能执行某个命令，不等于其界面、全部参数、图像交互和可选依赖已经移植。

0.10 新增：

- 序列工作区直接应用原版配准矩阵：四种输出范围、输出倍率、六种插值和钳位；也可选择六种 Drizzle 核、像素比例、主平场以及 8/32 位权重。
- 应用时按当前参与帧和原版质量筛选执行，每次输出独立命名，原图与旧结果保留。完成后打开输出序列，继续检查或叠加。新加入的未测量帧会提示先重新测量。
- 主平场可使用本任务的 master_flat.fits 或图库中已校准的同尺寸单通道主平场，运行记录保存平场副本和参数。序列页可删除整份任务，并通过最近删除恢复所有序列与权重。

0.9 已接入：

- 原版序列工作区：逐帧读取与缩放预览、显示通道、单张/范围包含与排除、参考帧选择；帧列表显示原文件编号。
- 使用原版两遍星点配准测得 FWHM、加权 FWHM、圆度、背景、星数与变换矩阵；质量图支持横纵轴切换、拖动帧序号查看对应帧，缺失数据不画成零。
- 原版序列统计及质量 CSV 导出。当前序列的参与帧选择直接用于原版叠加，保存独立的新结果、脚本和日志，复用原输入，不再复制整套照片。
- 帧参与和参考帧修改支持跨重启撤销/重做；新修改清除重做分支。写入日志保护原版非原子 `.seq` 写入，中断后恢复原序列和历史。
- 图库的“序列与质量图”、处理页的“建立序列”及处理记录均可进入。排除帧保留原图；释放存储请使用现有任务删除和永久删除。

0.8 已接入：

- Drizzle / Bayer Drizzle 接入原版一遍和两遍配准/应用流程；六种核、0.1–10 像素比例、0.1–3 倍输出、可选主平场初始权重、默认 8 位或匹配输出的 32 位权重。参数范围来自固定上游的原版界面和命令解析器。
- Bayer 输入保持马赛克，关闭校准后去马赛克，由原版 Drizzle 自动生成 RGB；RGB 或 X-Trans 输入不适用于该流程。平均值和求和叠加利用像素权重，其他合成方法保留原版行为。
- 原版权重文件保存在独立任务的 `process/drizztmp`，任务删除/恢复保留整套文件，永久删除任务后一起释放存储。覆盖安装仍可读取 0.7 的旧批处理参数。
- 2 倍输出约有 4 倍像素；Bayer 输出有 3 个通道并生成逐帧权重，处理需预留内存和存储。采集时的实际抖动有助于补足采样，软件放大不保证增加细节。

0.7 已接入：

- 校准高级参数：CFA 与去马赛克分开控制，平场 CFA 均衡、X-Trans 修复入口、暗场不缩放/噪声优化/按曝光缩放、主暗场冷/热坏点修正。单张校准输入无需复制成多张；平场仍先扣除偏置或暗平场。
- 全局星点一遍/两遍配准；两遍配准后实际运行 `seqapplyreg`。可选参考亮场、单应性/仿射/相似/平移、六种插值、钳位、星对/星数、通道、缩放及两遍输出范围。
- 平均/中位数/求和/最小/最大叠加；七种异常值剔除算法、参数、输入/输出归一化、快速归一化、RGB 均衡、四种权重和剔除图。
- FWHM、加权 FWHM、圆度、背景、星点数量筛选，百分比/绝对阈值/Sigma 阈值。界面参数保留，任务保存输入列表与生成时参数；实际执行以可编辑的脚本为准。
- 仍未完成原版全部功能。其他配准模式、更多序列交互与测光、合成偏置/BPM、重叠归一化/羽化等仍待接入；真实相机上的坏点、X-Trans 与 CFA 均衡需专项验证。

0.6 已接入：

- 图库单张/勾选批量删除；最近删除跨重启保留，支持恢复、永久删除和清空。恢复保留文件内容、帧类型和处理来源。
- 处理记录支持删除整份任务（输入副本、结果、中间文件和日志）；图库、任务和最近删除各显示存储占用。
- 删除前释放原版命令图像与序列缓存；删除当前显示文件会释放预览并清除选择。移入最近删除仍占存储，永久删除才释放空间。
- 单张处理结果（包括背景校正）可撤销/重做，恢复完整 FITS；历史跨重启保留，新处理分支清除重做链。
- 旧版结果未记录来源，不能补出可靠的撤销链。叠加结果切换、采样点与参数编辑、蒙版的撤销仍待移植；序列参与帧/参考帧撤销在 0.9 接入。

当前原生界面已接入：

- 多张 FITS 导入，亮场 / 暗场 / 平场 / 偏置 / 暗平场分类，勾选本次使用的文件，图库恢复。
- 上游 `readfits` 读取、图像信息、自动 MTF 预览，以及 FITS 结果导出。
- 原始 Siril 命令执行器：逐行同步运行 `.ssf` / 手动命令，显示原始日志，错误立即停止，可请求中止。
- 自动生成主校准帧、亮场校准、CFA 去马赛克、星点配准及可配置的叠加脚本。
- 单张参数界面：多项式背景提取、降噪、自动 / Asinh / 手动 MTF 拉伸、RGB 饱和度、裁剪与旋转；生成可编辑的原始 Siril 命令。
- 任务记录：恢复运行状态、脚本、日志、结果与中间 FITS，支持重新预览和导出。
- 长按图库文件可更改帧类型或只选该文件，竖屏预览顶部也可导入、处理和查看记录。
- 从实际编译的上游命令表生成可搜索的命令及参数列表，可插入脚本。

所有处理使用固定提交的 Siril 算法，在 iPad 本地完成。
这仍是原生移植测试版；桌面 GTK 窗口、在线星表服务、外部工具及部分可选格式尚未适配。
命令列表表示该内核的脚本入口，并不表示每个可选功能都已在 iPad 验证。

构建由 GitHub Actions 的 macOS 机器完成，本地可以只有 Windows 和 iPad。
工作流先编译目标依赖，再编译 Siril，并要求整个编译内核链接通过，最后生成
`SirilCore-iPadOS-arm64` 和 `SirilPad-unsigned` 两个构建产物。成功生成安装包后，
可在 Windows 上通过 [Sideloadly](https://sideloadly.io/) 本地签名并安装到连接的 iPad。
Apple 账号只用于本地签名，云端构建不需要 Apple 密码。

真机内存预算来自 `os_proc_available_memory`，当前处理使用可用预算的一半。
Apple 模拟器该 API 返回 0，回归测试改用保守的 512 MiB 可用预算，实际叠加预算为 256 MiB。
iPad 存储检查使用可用容量，而不依赖桌面文件系统类型说明。

使用批处理：

1. 在图库顶部选择帧类型，再分组导入各类 FITS；默认勾选新导入的文件。
2. 勾选同一目标、同一拍摄模式的亮场和匹配的校准帧。处理结果默认不参与下一次批处理。
3. 点“处理”，在校准、全局星点配准、叠加及质量筛选中设置参数，再生成脚本并运行。改参数后请重新生成脚本。
4. 运行期间保持 App 在前台；日志实时显示。完成后点结果名称预览，或用分享按钮导出 FITS。
5. 后期处理时只勾选一张图像或结果，生成单张处理脚本。自动拉伸预览不改变原始像素；后期脚本中的 `autostretch` 会改变新输出的像素。

默认不缩放暗场：暗场与亮场需相同曝光，温度、增益、偏置及拍摄模式也需匹配。
启用噪声优化或按曝光缩放时需同时导入偏置，先从主暗场扣除偏置，再缩放暗电流；亮场也单独扣偏置。
各张暗场必须具有相同曝光；按曝光缩放时亮场和主暗场均须有有效曝光元数据。有辉光的 CMOS 暗场通常应保持不缩放。
平场需偏置或暗平场；暗平场需与平场相同曝光。完整流程可编辑为其他 Siril 原生脚本。
不缩放的主暗场保留偏置信号，亮场有主暗场时不会再重复扣偏置；平场优先用主暗平场，否则扣主偏置。

每次任务在 `Documents/Jobs/<UUID>` 创建独立目录，复制勾选文件并保存 `processing.ssf`、`processing.log`、`job.json`、`inputs.json`、生成时的 `batch-options.json`、输出和中间文件。导入或单张脚本没有批处理参数文件。
原生界面的“记录”可重新打开以前任务。App 退出后不能继续处理，被中断的任务会显示对应状态。
“文件”App 的 Siril iPad 目录可直接访问这些文件。中止或失败保留已经生成的结果。
脚本初始工作目录包含 `lights`、`darks`、`flats`、`biases`、`flatdarks`、`results` 和 `process`；
外部 `.ssf` 的文件路径需要对应这些目录。`exit`、后台实时叠加和 `@` 启动脱离管理的脚本不在嵌入入口开放。

下载原生测试版：

[版本与安装包](https://github.com/BackerMrW/siril-ipados/releases)。

安装真机测试版：

1. 从版本页面下载 `.ipa`；也可打开成功的真机目标构建，在页面底部下载 **SirilPad-unsigned**，解压取得 `.ipa`。
2. 在 Windows 安装 Sideloadly，用 USB 连接 iPad 并选择“信任此电脑”。
3. 把 `.ipa` 拖进 Sideloadly，选择 iPad，使用自己的 Apple ID 本地签名安装。
4. 按 iPad 提示信任开发者；如提示需要开发者模式，在“设置 → 隐私与安全 → 开发者模式”开启并重启。

免费 Apple ID 签名通常有效 7 天，之后需要重新签名。

[构建记录](https://github.com/BackerMrW/siril-ipados/actions/workflows/ipados-preflight.yml)
会分别显示依赖、内核链接、App 构建的结果。编译及链接成功不代表已在 iPad 上运行验证。
`dist/BUILD.json` 记录打包时使用的上游提交与静态库。

构建基线是 iPadOS 17、arm64，关闭 GTK、OpenMP、外部进程启动及部分可选文件格式和网络功能。
桌面 GTK 界面需要逐项接入原生界面。

主要文件：

- `native/siril-ipados.patch`：上游 Siril 的最初 iPadOS 构建适配。
- `native/SirilCore.c`：串行化调用上游内核的 C 接口。
- `tools/build-ipados-deps.py`：固定版本目标依赖与 Apple 框架适配。
- `tools/embed-siril.py`：把 C 接口及完整链接检查接入上游构建。
- `tools/package-siril.py`：把实际参与链接的目标静态库打包为 XCFramework。
- `tools/source-bundle.py`：收集固定版本源代码、子模块、依赖和构建脚本，用于版本发布。
- `app/`：调用内核的原生 iPad 界面。
