# Siril iPad 0.7.0 验证记录

本轮补充校准、全局星点配准与叠加参数界面；没有宣称完整桌面功能已经移植。所有计算使用固定的 Siril 原版内核。

## 科学计算检查

- 三张具有不同已知像素值的 FITS：平均值、中位数、最小值、最大值符合对应运算；求和符合原版将最大结果缩放到 1 的行为。
- 十一张近似相同的 FITS，其中一张有明显高异常值：Winsorized、Sigma、MAD、Median Sigma、线性拟合、广义 ESD、百分位剔除均降低其贡献。分别保存高低剔除图的原版路径被实际执行。
- 具有已知平移的 256×256 星场：两遍检测/匹配后实际执行 `seqapplyreg`，检查叠加后的参考星位置及相邻错位位置。覆盖四种变换、六种插值；这是各参数的覆盖，不是全部组合的穷举。
- 实际按 0.5 倍配准，输出尺寸确认为 128×128；没有仅以命令成功代替尺寸校验。
- 加法、加法缩放、乘法、乘法缩放归一化，以及噪声、星数、加权 FWHM、已叠加帧数权重实际运行，检查参考星仍被保留。
- 五项质量筛选在保留 100% 的配置下组合执行。百分比的其他值、绝对阈值和 Sigma 阈值的完整数学覆盖仍待补充。

## 原生 App 流程检查

- 使用 Swift 界面实际使用的脚本生成器与任务执行器，校准 120 秒亮场和 240 秒暗场，曝光缩放系数为 0.5。
- 分别使用一张及三张偏置、暗场和平场；检查输出四个像素符合 `(亮场 − 偏置 − 0.5 × (暗场 − 偏置)) × 平场均值 / 已扣偏置平场`。
- 单张平场通过原版 `calibrate_single` 校准。原版普通序列要求至少两张，不能给单张平场调用 `calibrate`。
- 相同校准后图像在各归一化模式下保持已知像素值；不缩放时曝光不匹配，以及不插值配准却改变倍率的配置会被生成器拒绝。
- 任务保存并重新读取 `batch-options.json` 与 `inputs.json`，验证暗场优化方式、剔除方式、输入数量和输入 UUID；高级参数可编码后恢复。
- 在真实 SwiftUI App 中打开校准、配准与叠加页面，用新鲜就绪标记检查加载，并捕获三张界面截图。截图不代替真实触摸和输入测试。
- 删除/恢复、中断恢复、永久清理、任务保护、FITS 撤销/重做、原版工作区内存释放及背景/分析工作区继续运行既有回归检查。
